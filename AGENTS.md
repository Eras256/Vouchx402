# Vouch402

x402-metered on-chain risk intelligence for autonomous agents on Base, with
a built-in proof-of-fulfillment attestation layer (x402-SAP). Stack:
Express + viem + EAS SDK on Base. Full spec: `docs/TECHNICAL_SPEC.md`
(source of truth; `web/content/technical-spec.md` is a synced copy the
Docs page reads — see `web/scripts/sync-docs.mjs`, run it after editing
the root spec).

## Repo layout

- `src/` — the resource server (Express). `server/` (x402 quote issuance,
  payment verification, `/v1/metrics`, `/v1/disputes`), `scoring/` (v0 risk
  heuristic, reads Blockscout's public Base API), `attestation/` (x402-SAP:
  EAS schema registration, fulfillment/dispute attestations), `lib/`
  (env/config, viem chain clients, SQLite persistence, EAS/ethers signer,
  Foundry-keystore decryption).
- `sdk/` — `vouch402-sdk` (npm), the TypeScript client library. `cli/` and
  `mcp-server/` both depend on it rather than duplicating payment-flow code.
- `cli/` — `vouch402` (npm), `vouch402 score <address>` from a terminal.
- `mcp-server/` — `vouch402-mcp-server` (npm), a standalone MCP server;
  never holds a wallet or signs a transaction itself.
- `web/` — the Next.js frontend at https://www.vouch402.xyz (Docs page,
  live Try It demo, activity feed, `/pitch` deck). Pure client of the API
  above, no server-side logic of its own. Has its own `web/AGENTS.md`
  (Next.js-version-specific notes, auto-regenerated by `next dev` — don't
  hand-edit it, just commit it if `next dev` re-adds it).
- `contracts/` — on-chain pieces (EAS schemas are registered via the SDK,
  not deployed as custom contracts; see `docs/TECHNICAL_SPEC.md`).
- `plugins/vouch402.md` — the Base MCP plugin definition, submitted
  upstream to `base/skills`.

All four packages (`vouch402`, `vouch402-sdk`, `vouch402-mcp-server`, and
this root API) are versioned and released together when a change spans
them — check `DECISION_LOG.md` for the current published versions before
assuming what's live on npm.

## Conventions specific to this repo

- **`DECISION_LOG.md` is mandatory for anything non-trivial.** Every real
  decision, bug fix, or finding gets a dated entry: what happened, why,
  and — critically — how it was *verified*, not just that it was built.
  It's a public asset showing judgment, not a private scratchpad: no
  budget figures, no grant framing, no competitor-named comparisons.
  Match its existing narrative style; read a few recent entries before
  adding one.
- **"Committed" is not "live."** This project has been burned once by
  assuming a local build/commit meant the deployed site reflected it (52
  unpushed commits sat locally for a full session while every "verified
  live" claim was quietly only true of the API, not the Vercel-deployed
  frontend — see the `DECISION_LOG.md` entry on the "publicResult doesn't
  render" bug). After any change meant to be live, verify against the
  actual production surface: `gh api repos/Eras256/Vouchx402/readme` for
  README changes, a real page load / Playwright screenshot of
  `https://www.vouch402.xyz` for frontend changes, a real `curl` against
  `https://vouch402.fly.dev` for API changes, `gh issue view <n>` (a
  separate read, not the `gh issue create` output) for filed issues.
- **Privacy model**: scored results are attestation-only on the public
  activity feed by default (no address/score/signals shown) unless the
  payer sets `makePublic: true`, or it's the team's own dev/test wallet
  (`src/constants/devWallet.ts`), which is public-by-default. See
  `DECISION_LOG.md`, "Dev wallet shows full results by default."
- **No raw private keys anywhere.** Every signer path decrypts a standard
  Foundry keystore (`cast wallet import`/`new`) via
  `ethers.Wallet.fromEncryptedJsonSync`; see `src/lib/keystore.ts` and
  `cli/src/keystore.ts`.

## Commands

```bash
npm install
npm run dev                # server on $PORT (default 3402)
npm test                   # Base Sepolia integration tests, real on-chain txs
npm run build               # -> dist/
npm run demo                 # scripts/demo.ts: full x402 flow end-to-end
npm run register:schemas      # register EAS schemas for a network (idempotent)
```

Frontend (`web/`): `npm run dev`/`build`/`start` as usual for Next.js;
`npm run build` also runs `scripts/sync-docs.mjs` as a `prebuild` step.

## Deployment

- API: Fly.io (`fly deploy --app vouch402`), `NETWORK=base` in production.
  Deployer keystore is a Fly secret, decrypted only in memory at process
  start — see `DECISION_LOG.md`, "Split payTo (treasury) from the signer
  wallet."
- Web: Vercel, auto-deploys from `origin/master` via GitHub integration —
  a `git push` is required, `flyctl deploy` does not touch it. Root
  Directory is set to `web`, so the frontend cannot read files outside
  that directory at runtime (hence the `sync-docs.mjs` copy step above).
